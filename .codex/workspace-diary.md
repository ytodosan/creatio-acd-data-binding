## 2026-09-30 - AcdDataBindingNet: GlbDataBinding port for .NET Framework and .NET
Context: GlbDataBinding only works on .NET Framework. The new package AcdDataBindingNet (standalone port) was created in the repo and linked into Y1DEV with L4R.
Decision: The backbone moved server-side. AcdDataBindingService (GetPackages, RestoreColumnSetup, SaveBindings) and DataBindingStore save bindings through the PUBLIC Terrasoft.Core.Packages.PackageElementUtilities (SavePackageSchemaDataInfo, SavePackageSchemaDataColumns, LoadData). This is the reachable part of the platform SaveSchemaDataCommand. The client (AcdDataBindingMixin + 13 replacing classic schemas, generated from pulled Glb files) only selects records and names bindings. The visibility gate is CanManageSolution (no custom operation or data). The tool's own package is excluded from targets.
Discovery: Glb's only hard .NET blocker in its own C# is ServiceStack.Text (it isn't in the netstandard SDK). The platform SchemaDataDesignerService has CoreServiceRoute, so it also exists on .NET. ISchemaDataElementUtilities, IPackageValidator, IPackageElementDependencyApplier, GlobalAppSettings.FeatureAutoAddPackageDependencies and SchemaManager.GetInstanceFromMetaData are all INTERNAL, so config code can't validate or auto-add dependencies. The store instead binds only columns whose CreatedInSchemaUId package is in the target hierarchy, and reports the rest as warnings. Data-localization methods exist only on newer builds (called via reflection when the IncludeDataLocalizationInPackage feature is on). SavePackageSchemaDataInfo returns Guid.Empty on a lock or name clash. Y1DEV is Creatio 10.0.0.858 (net472), while the cached SDK is 8.1.3. Local build setup: .application/net-framework/{core-bin,packages,bin} are junctions into Y1DEV; .application/net-core/core-bin is a copy of .nuget creatiosdk netstandard2.0 DLLs. The netstandard build needs a compile-only Common.Logging PackageReference. clio's active env is the stale 'BooksDev5' (pass -e Y1DEV). This is likely the cause of the MCP "settings bootstrap is broken" error. Git Bash rewrites '/0/rest/..' service paths: use MSYS_NO_PATHCONV=1 and no leading slash with clio call-service. `clio add-package` also added the new package to UsrYacht/Files/app-descriptor.json (reverted). UsrYacht.csproj lacks the .build-props import, so the MainSolution build fails on UsrYacht (pre-existing).
Files: packages/AcdDataBindingNet/Files/src/cs/**, packages/AcdDataBindingNet/Schemas/**, packages/AcdDataBindingNet/Resources/AcdDataBindingMixin.ClientUnit/resource.en-US.xml, packages/AcdDataBindingNet/descriptor.json, tests/AcdDataBindingNet/**

## 2026-10-06 - Forced update on Name for lookup values
Context: Bound lookup values (Bind data, Bind all data) had no forced-update columns, so a renamed value never reached environments where the package was already installed, even after actualizing the data.
Decision: The default rule in BindingColumnRules (used by every schema without a dedicated rule: regular lookups and SysAdminUnit roles) now force-updates Name. DataBindingStore applies it per bound column, so schemas without Name are unaffected. Dedicated rules (SysProfileData, SysSettings*, SysAdminOperation*, SysWorkplace*, Lookup) are unchanged.
Discovery: Trade-off: installing the package overwrites a Name renamed locally on the target environment. Roles share the default rule, so their Name is forced too (the user was told and can opt out). Re-binding through the tool rewrites the binding's column settings (SavePackageSchemaDataColumns deletes and recreates them), so manual designer tweaks are lost on re-bind.
Files: packages/AcdDataBinding/Files/src/cs/DataBinding/BindingColumnRules.cs, tests/AcdDataBinding/DataBinding/BindingColumnRulesTests.cs, README.md
Impact: 32 tests pass on net472, and both frameworks build. Deployed to Y1DEV (restart). Existing bindings change only when re-bound.

## 2026-10-06 - Workplace binding split: new workplace vs sections
Context: "Bind workplace" always bound the workplace header, its sections and its roles. For workplaces shipped with Creatio apps (e.g. Customer 360) the header already exists on the target, and role access is a per-environment decision, so those bindings were unnecessary.
Decision: The Bind workplace button is now a drop-down: "Bind new workplace" (onBindNewWorkplaceClick, the original 3 bindings) and "Bind sections" (onBindWorkplaceSectionsClick, SysModuleInWorkplace only, as a main binding, so a workplace without sections reports "No records found"). Both use createWorkplaceSectionsBinding, so the sections binding has the same name and UId and re-binding updates one binding. New localizable strings BindNewWorkplaceCaption and BindWorkplaceSectionsCaption were added to the mixin's metadata.json (B2) and resource.en-US.xml.
Discovery: Caveats told to the user: (1) the target package must depend on the app packages that provide the workplace and the sections; the tool can't add dependencies. (2) All of the workplace's sections are bound, including the vendor's own rows. They match on the SysWorkplace + SysModule key, so they don't duplicate, but forced Position means the package's order wins. A later improvement could let the user pick sections. SysLocalizableValue uses the column [Key] (not ResourceKey) for checking captions.
Files: packages/AcdDataBinding/Schemas/AcdDataBindingMixin/{AcdDataBindingMixin.js,metadata.json}, packages/AcdDataBinding/Resources/AcdDataBindingMixin.ClientUnit/resource.en-US.xml, packages/AcdDataBinding/Schemas/SysWorkplacePageV2/SysWorkplacePageV2.js, packages/AcdDataBinding/Schemas/SysWorkplaceSectionV2/SysWorkplaceSectionV2.js, README.md
Impact: Client-only change: pkg-to-db, no restart. Verified schema content and captions in the DB.
